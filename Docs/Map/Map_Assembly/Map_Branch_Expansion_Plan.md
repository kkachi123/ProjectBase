# 맵 분기 확장 계획

## 목표

주 경로에서 여러 선택 방으로 왕복할 수 있게 해 접근 가능한 방을 늘린다. 세 방향·네 방향 방과 막다른 방을 실제 이웃 방에 연결하고, 방 목표를 완료하지 않고 주 경로를 우회할 수 없게 한다.

## 연결 구조

- 기존처럼 시작부터 Goal까지 좌우·하강 주 경로를 먼저 만든다. 주 경로의 중간 방에서만 좌우로 선택 방을 연결한다.
- 선택 방은 출입구가 하나인 막다른 방이며 한 주 경로 방에만 연결한다. 현재 단계에서는 선택 방끼리 이어지거나 다른 주 경로 방과 연결되지 않는다. 인접한 방이라도 계획에 없는 방향은 벽으로 닫는다.
- 기본 4×4 설정에서는 선택 방을 최대 3개까지 추가한다. 위치와 방향, 통과 가능한 프리팹이 부족하면 가능한 만큼만 만들고 나머지는 닫힌 방으로 채운다. Side 방의 정확한 목표 수는 연결 가능한 후보와 생성 결과를 확인해 정한다.
- 주 경로 방 하나에서 좌우 두 분기가 모두 가능한 경우 네 방향 방을 후보로 사용한다. 예를 들어 북→남 주 경로에 동·서 선택 방 두 개를 연결한다. 세 방향 방은 주 경로와 선택 방 한 개를 연결한다.
- 같은 방의 분기 방향을 각각 별도 비트로 보관한다. 필수 경로의 `Entry`·`Exit`은 유지해 목표 출구는 `Exit`만 잠그며 분기와 입구는 열린다. 선택 방이 다른 주 경로로 이어지지 않으므로 잠긴 출구를 방 밖으로 우회하지 못한다.

## 생성과 검증 계약

- 분기 후보의 연결 방향 집합을 먼저 정한 뒤 해당 출입구가 정확히 일치하는 템플릿을 고른다. 좌우 두 분기는 함께 평가해, 중간에 대응하는 세 방향 방이 없더라도 네 방향 방을 선택할 수 있게 한다. 위치·후보 순서는 정렬한 뒤 seed 기반 난수로 정하며 두 분기 후보를 한 방향 후보보다 먼저 검사한다.
- 각 분기 방에서 주 진입→주 출구, 주 진입→각 분기, 각 분기→주 출구를 실제 Player로 검증한 템플릿만 사용한다. 선택 방은 해당 출입구의 입장·복귀가 검증돼야 한다. 여러 분기 사이를 직접 이동하는 통과 방향도 방에서 실제로 지원하고 검증한 경우에만 선택한다.
- 같은 seed·설정·카탈로그에서 같은 경로와 분기를 만든다. 방 역할에 따른 콘텐츠·함정 선택, Base 그룹 우선 선택과 Variant 선택은 유지한다. 기존 seed의 결과는 조합 규칙과 카탈로그 변경으로 달라질 수 있다.
- 분기를 만들며 주 경로 템플릿을 교체하면 최종 선택된 템플릿의 목표·콘텐츠·함정 설정이 적용된다. 기존 `WestSouth`의 목표나 다른 방의 콘텐츠가 분기 후보에 자동으로 복사되지는 않는다. 확장 후 대표 조건 방의 출현과 목표 연결을 확인하고, 필요한 후보는 명시적으로 설정한다.
- 선택 가능한 분기가 없어도 유효한 주 경로는 생성한다. 템플릿 부족이나 연결 실패가 목표 출구를 우회하거나 출입구 불일치로 이어지지 않게 검사하고, 주 경로 자체를 만들 수 없으면 기존 제한 횟수 후 실패 사유를 반환한다.

## 작업 순서

1. [x] **연결 구조 설계:** 분기 개수·방향, 주 경로와 출구 잠금, 통과 및 실패 조건을 정한다.
2. [x] **맵 조합 로직:** 여러 분기 방향을 계획에 저장하고 후보 선택·인접 출입구·왕복 검증을 확장했다. 현재 카탈로그와 자동 테스트용 네 방향 후보로 계획 생성·검증을 확인했다.
3. [x] **Variant 구성:** `CapEast`·`CapWest` 선택 방과 `DownThrough` 네 방향 방을 제작해 등록했다. 실제 Player로 기록된 일곱 통과 방향과 양쪽 선택 방의 왕복을 확인했고 기존 세 방향 Variant의 맵 계획 연결을 검사했다. [검증 결과](../Map_Refactoring_Log.md#선택-방과-네-방향-variant-구성).
4. [x] **맵 조합 검증:** 1,000개 seed의 분포·재현성을 확인하고 Base 20종의 실제 생성을 검사했다. 대표 맵 두 개에서 Player가 각 선택 방 세 곳을 왕복하고 Goal에 도달했다. [검증 결과](../Map_Refactoring_Log.md#대표-맵-조합-검증).
5. [ ] **방 내부 조합 검증:** 조건 방의 잠금·개방과 분기, 함정·복수 목표 조합 및 가시·가시 공·낙하 발판의 동시 배치를 확인한다.

각 단계가 끝나면 결과를 보고하고 커밋한 뒤 멈춘다. 반복 Player 검증이 많아질 경우 범위를 먼저 확인받는다.

## 검증 기준

- 여러 선택 방과 좌우 두 분기를 가진 네 방향 방이 생성될 수 있고, 모든 열린 면은 맵 안의 인접 방과 서로 연결된다.
- 주 경로는 시작에서 Goal까지 연결되며 선택 방은 주 경로에 한 번만 연결된다. 누락된 이웃, 잘못된 출입구·방향, 미검증 통과, 순환과 목표 출구 우회가 있는 계획은 거부한다.
- 기본 카탈로그와 네 방향 후보를 포함한 테스트 카탈로그에서 seed별 성공·재현성, 방 역할·콘텐츠·함정의 선택과 빈 후보의 처리를 검사한다.
- 최종 카탈로그의 0~999 seed에서 Side 방과 분기 수의 분포, 모든 등록 Base의 등장 여부를 기록한다. 대표 seed에서 다중 분기·네 방향 방의 실제 입장과 복귀, 주 경로의 목표 잠금·개방과 Goal 도달을 확인한다.
