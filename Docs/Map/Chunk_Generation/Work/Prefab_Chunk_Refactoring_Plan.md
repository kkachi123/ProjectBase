# 프리팹 및 Chunk 내부 생성 리팩토링 계획

## 목표

프리팹을 기능별로 정리하고 Chunk의 지형·콘텐츠·함정·목표 설정을 분리한다. 실제 생성된 콘텐츠에 적용할 수 있는 목표 규칙 하나를 선택해 주 경로 출구를 자동으로 잠근다.

## 작업 순서

1. [x] **프리팹 정리:** 플랫폼·Goal·몬스터·카메라·투사체를 기능별로 배치했다. 이동 대상 GUID 1,411개와 1,000개 seed 계획, 맵 EditMode 테스트 78개 및 Title→InGame의 Player 생성을 확인했다.
2. [x] **Chunk 설정 분리:** 지형·플랫폼, 몬스터·아이템, 함정의 설정과 적용 책임을 분리했다. Base 20개·Variant 21개의 설정을 대조하고 두 선택 방의 Override를 유지했다. 1,000개 seed 계획과 맵 테스트, 대표 Player 이동을 확인했다.
3. [x] **목표 규칙:** 실제 콘텐츠·트리거에 적용 가능한 ScriptableObject 규칙 하나를 seed로 선택한다. 규칙·분기와 사망 이벤트는 자동 검사했고 실제 Player의 지점·스위치 완료를 확인했다. 실제 몬스터 처치 후 개방은 통합 검증에 남긴다.
4. [ ] **자동 출구 문:** 주 경로 출구에 공통 문을 자동 배치하고 목표 완료 시 Collider를 해제한 뒤 DOTween 페이드로 연다.
5. [ ] **통합 검증과 문서화:** 실제 Player의 몬스터 처치 후 개방과 대표 방·분기·함정·목표 조합을 확인하고 설정 가이드와 진행 현황을 갱신한다.

각 단계 완료 시 검증 결과를 보고하고 커밋한 뒤 다음 지시를 기다린다. 반복 Player 검증이 많아질 경우 횟수와 범위를 먼저 확인받는다.

## 구현 기준

- 에셋 이동은 Unity에서 GUID를 유지하고 씬·프리팹·카탈로그 참조, 직접 경로와 문서를 갱신한다. 기존 후보·가중치·검증 표시·Variant Override를 보존한다.
- 방과 패턴의 RuleTile 이웃 판정을 위해 확정된 지형의 공통 그래픽 Tilemap을 유지한다.
- 목표 규칙은 적용 가능 여부와 목표 생성의 공통 인터페이스를 제공한다. ScriptableObject는 설정을, 각 방은 독립적인 진행 상태와 이벤트 구독을 관리한다.
- 전체 몬스터 처치, 랜덤 몬스터 한 개체 처치, 지점 도달, 스위치 작동을 지원한다. 지점·스위치 규칙은 해당 종류의 실제 후보를 모두 완료하고, 랜덤 몬스터에는 임시 표시를 붙인다.
- 실제 콘텐츠와 트리거 후보를 결정한 뒤 적용 가능한 규칙을 선별한다. 조건 방 출현 확률의 기본값은 50%이며 조건 방·규칙·대상 선택은 seed로 정한다. 후보가 없으면 문은 열린다.
- 생성 직후 목표와 주 출구 잠금을 설정한다. 입구와 선택 방 분기는 열어 두고, 입장 전 처치와 재입장 상태를 반영하며 Run 종료 시 이벤트와 Tween을 정리한다.
- 대표 `WestSouth` 방과 분기가 있는 대표 방에 규칙을 설정한다. 정식 목표 UI는 UI 작업에서 구현한다.

## 검증 기준

- GUID, 씬·프리팹 참조와 Variant Override, 에디터·테스트 직접 경로, 에셋 이동 전후 같은 seed의 지형·콘텐츠·함정 선택을 확인한다.
- 규칙별 대상 유무와 다수 대상, 같은 seed 재현성, 동일 ScriptableObject를 사용하는 방의 상태 독립성을 검사한다.
- 네 방향 문 위치·Collider와 페이드·정리를 확인한다. 실제 Player로 대상 표시, 목표 완료와 잠금·개방, 입장 전 처치, 재입장, 분기 왕복과 Goal 도달을 확인한다.
- 용암은 보류하고 난이도별 몬스터·아이템·함정 출현 확률은 방 조합 검증 이후 진행한다.
