# 방별 진행 조건 계획

현재 구현과 이전 검증 범위를 기록한다. 목표 규칙과 자동 문의 다음 구현은 [프리팹 및 Chunk 리팩토링 계획](Prefab_Chunk_Refactoring_Plan.md)을 따른다.

## 목표

일부 방에서 실제 생성된 목표를 모두 완료하면 주 경로 출구가 열린다. 최종 클리어는 GoalTrigger 도달 시 처리한다.

## 동작

- 방 제작자는 규칙 목록과 트리거 후보를 지정한다. 실제 생성된 몬스터와 확률로 선별된 트리거를 바탕으로 적용 가능한 규칙 하나를 선택한다.
- 전체 몬스터 처치, 임의 몬스터 한 마리 처치, 지점 도달, 스위치 작동을 지원한다. 선택된 규칙의 목표를 모두 완료해야 하며 목표가 없으면 출구를 열어 둔다.
- 주 경로 출구만 잠그고 입구와 선택 방 분기는 유지한다. 목표 진행과 출구 개방은 Run 동안 유지한다.
- 목표는 생성 직후부터 추적해 입장 전 처치도 반영한다. 빠른 이동으로 잠금을 우회할 수 없어야 한다.
- 제작·검증 중에는 목표 종류·진행 수, 목표 달성 및 출구 개방을 임시 표시와 효과로 확인한다. 정식 목표 UI는 [UI 작업](../../../UI/UI_Progress.md)에서 제작한다. 방 목표 로직은 UI 표현에 의존하지 않으며 UI가 현재 방과 목표 상태를 조회하고 변경을 반영할 수 있도록 연결한다.

## 작업 순서

1. [x] 기존 방 하나에 트리거·몬스터 목표, 입장 판정, 출구 잠금과 상태 유지를 구성하고 임시 표시·효과로 동작을 검증했다. [실제 검증 범위](../Chunk_Generation_Progress.md)를 따른다.
2. [x] 실제 콘텐츠·트리거 선택 결과를 목표에 연결하고 빈 목표와 seed 재현성을 검증했다. 대표 `WestSouth` 방에서 남쪽 출구와 지점·스위치·몬스터 목표를 확인했다. 동·서·남·북 출구 선택은 자동 검사로 확인했으며 실제 Player 검증은 대표 방에 한정된다.
3. [ ] 조건 방과 일반 방, 분기·함정·복수 목표의 대표 조합을 실제 Player로 검증한다. 이후 방·콘텐츠 확장과 난이도별 확률을 진행한다.

정식 목표 UI는 UI 작업에서 구현한다. 용암은 보류하며 재개 시 에셋과 동작을 정한 뒤 독립 검증과 대표 방 배치를 진행한다.

각 순서 완료 시 결과를 보고하고 커밋한 뒤 다음 지시를 기다린다. 반복 Player 검증이 많아질 경우 범위를 먼저 확인받는다.

## 검증 기준

- 각 규칙에서 선택된 종류의 목표를 모두 완료해야 출구가 열린다. 여러 종류가 후보로 있어도 규칙 하나만 선택한다.
- 목표가 없는 방은 잠기지 않고, 입장 전 처치·재입장·중복 트리거에도 진행 수가 정확하다.
- 실제 생성 맵에서 주 출구 잠금, 기존 입구·분기 이동, 목표 접근과 Goal 도달을 확인한다.
- 대표 seed의 지형·함정·목표 조합과 같은 seed 재현성, 실제 화면의 임시 표시·효과, Run 종료 후 정리를 확인한다.
