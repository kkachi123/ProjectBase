# Base·Nova Variant 작업 지침

## 목표

Base에서 방의 연결·충돌 지형·내부 랜덤 조합을 관리하고, 이를 상속한 Nova Variant로 배경과 장식을 구성한다. 세부 단계와 완료 상태는 [Chunk 내부 생성 진행 현황](../Chunk_Generation_Progress.md)을 기준으로 한다.

## 제작 기준

- Base에는 출입구와 검증된 통과 방향, 고정 충돌 지형, 변형·보호 영역, 패턴과 확률 셀, 콘텐츠 슬롯·설치 조건과 마커를 둔다. 지형 구조가 다른 방은 별도 Base로 구분한다.
- Nova Prefab Variant에는 고유 템플릿 ID와 Nova 배경·장식을 지정한다. 배경 Sprite와 물리 장애물의 역할을 구분하고, 플레이에 영향을 주는 콘텐츠는 슬롯의 설치면·여유 공간에 맞춘다.
- 일반 경로 방은 일반 몬스터와 아이템을, 선택 방은 아이템과 엘리트 몬스터를 후보로 둔다. 방의 최종 역할에 맞게 후보 종류를 걸러 선택한다. 현재 일반 방 슬롯은 `WestSouth` Base에만 설정돼 있고 엘리트 몬스터는 프리팹 제작 후 연결한다.
- 콘텐츠는 방과 분기가 확정된 뒤 선택하고 검증한다. 출입구·시작 위치·목표와 슬롯 사이의 안전 공간, 슬롯 간 겹침, 내부 지형 변형에 따른 설치면과 여유 공간을 확인한다. 슬롯별 후보와 빈 상태의 가중치는 제작 데이터로 정한다.
- 기존 Nova 시제품의 지형과 장식을 조사해 필요한 Base와 Variant에 활용한다. 닫힌 방과 선택 방 분기를 포함해 맵 생성에 필요한 역할을 확보한다. 기존 Base가 해당 역할을 제공하는지 확인하고 부족한 경우에만 추가한다.
- 대표 Base와 Variant에서 변형·통과 조건의 상속과 생성 결과를 먼저 확인한다. Base의 지형·패턴·통로 또는 Variant의 물리 조건이 달라지면 영향을 받는 검증 표시를 해제하고 관련 통과와 조합을 다시 확인한다. 현재 표시는 자동 해제되지 않는다.
- 방 선택은 출입구·역할·검증 조건을 만족하는 후보 중 Base 그룹을 먼저 고르고 그 그룹의 프리팹을 고른다. Base에 기록한 고정 식별자를 Variant가 상속한다. 그룹 ID가 비어 있으면 템플릿 ID를 사용하며, 같은 그룹의 방 유형과 출입구는 같아야 한다.
- 현재 내부 지형 난수는 템플릿 ID를 사용하므로 같은 Base와 seed라도 Variant ID에 따라 결과가 달라질 수 있다. 같은 설정·카탈로그·코드와 seed의 결과는 재현하고, 선택 방식이나 ID가 바뀌면 기존 seed의 결과도 달라질 수 있음을 검증한다.
- [NovaDevs 그래픽 설계](NovaDevs_Level_Art_Design.md)와 [배치 규칙](Room_Art_Authoring_Guide.md)을 따른다. 고정 지형에 붙는 장식은 고정 지형에 배치하고 변형 영역 근처의 장식은 각 지형 조합에서 확인한다.
- Nova Variant만 등록한 카탈로그와 지형 RuleTile·머티리얼을 맵 설정에 지정한다. 에셋 이동 시 Unity GUID와 참조를 유지하고, 기존 Base 전용 카탈로그·설정은 씬·에디터·테스트의 참조 전환과 검증 후 정리한다. Base 프리팹은 Variant의 부모로 유지한다.
- 공통 그래픽 Tilemap은 확정된 지형을 표시한다. 현재 콘텐츠 설치면과 그래픽 수집은 전체 셀이 충돌하는 Grid 타입 지형을 기준으로 한다.

## 함정 제작·배치 계획

- 화살 함정은 `Assets/Prefabs/Trap/Bullet/`의 투사체 에셋을 사용한다. 발사기는 Sprite 없이 투명한 프리팹으로 만들고, 추후 Sprite를 추가할 수 있게 한다. 투사체의 크기·피벗·가독성과 발사 방향을 확인한다.
- 화살 함정은 활성화 후 초기 대기 시간을 두고 지정된 간격으로 수평 투사체를 발사한다. 발사 위치·좌우 방향·속도·간격·초기 대기·피해량·최대 수명은 프리팹에서 조절한다. 첫 검증용 값은 초기 대기 2초, 간격 2초, 속도 초당 5유닛, 피해 1, 수명 4초로 두고 실제 플레이 검증 후 조정한다.
- 발사기는 발사 시점·방향과 투사체 풀을, 투사체는 직선 이동·충돌·피해·수명을 담당한다. 투사체는 중력을 사용하지 않고 Player에게 `IDamageable`로 한 번 피해를 주거나 Ground·Wall에 닿으면 풀로 돌아간다. 지정 대상이 아닌 Trigger와 발사기 자신은 무시하며, 충돌하지 않아도 최대 수명에 반환한다. 발사기 비활성화 시 발사를 멈추고 소속 투사체를 회수하며, 파괴 시 풀을 정리한다.
- 기존 `CircleBullet`의 Sprite와 애니메이션을 사용하는 별도 함정용 투사체를 만들었다. 발사기별 `ObjectPool`은 반환된 투사체를 최대 32개까지 보관하며 필요할 때 재사용한다. 기존 풀 기반 `PooledTrapBullet`은 새 투사체에서 실행하지 않고 기존 프리팹과 사용처는 유지한다.
- 대표 방 배치 시 발사체 시작점이 벽에 겹치지 않아야 하며 좌우 방향을 실제 월드 방향으로 확인한다. 화살 함정 프리팹은 독립 환경에서 초기 대기·반복 발사, 좌우 이동, Player 피해, 지형 충돌, 수명과 중지·정리를 검증한다.
- `Base/NorthEast`에는 `(1.4, 5)`의 서쪽 벽 발사 후보가 기본 비활성으로 배치되어 Variant에 상속된다. 오른쪽으로 초당 5유닛, 수명 3초로 발사해 동쪽 출입구 전에 풀로 반환된다. 독립 방과 생성 맵에서 함정 유무에 따른 실제 Player 북→동 통과와 점프 회피를 확인했다. 단계마다 결과를 보고하고 다음 지시를 기다린다.
- Base의 함정 슬롯에 후보·설치 공간·지지면과 생성·빈 상태 가중치를 지정한다. 중간 경로 방과 선택 방에서 각 후보의 생성 여부를 선택하며 시작·Goal·닫힌 방은 선택하지 않는다. 같은 설정과 seed에서는 같은 선택을 재현한다. 현재 화살·Spikes·Fire 후보가 각각 1:1 가중치로 등록돼 있다.
- 화살 트랩은 발사 공간을 확보한 벽면에 배치한다. 발사기가 보이지 않으므로 투사체의 가독성과 실제 Player가 회피할 수 있는 조건을 확인한다. 용암은 건널 발판과 착지 지점을 갖춘 지정 영역에서 채움 또는 빈 상태를 선택한다.
- 맵 생성은 후보 선택과 활성화를 담당하고 함정의 발사·동작·피해는 각 함정 프리팹이 담당한다. 정적 검사는 설정된 공간과 지지면의 지형·변형 영역·콘텐츠 공간·출입구 겹침을 확인한다. 투사체의 실제 이동 범위나 Player 통과는 정적 검사로 보증하지 않는다. 발사 위치·방향·속도·수명이나 방 지형이 바뀌면 `passageVerified`를 해제하고 범위와 이동을 다시 확인한다.
- `Spikes`는 `TrapContactDamage`로 Player 접촉당 피해 1을 준다. 접촉 유지 중에는 추가 피해가 없고 완전히 벗어난 뒤 다시 접촉하면 피해를 준다. 함정이 비활성화되면 접촉 기록을 비운다. Sprite의 보이는 영역에 Trigger를 맞췄고 대표 방의 통과와 확률 배치를 확인했다.
- `Fire`는 `FireTrap`으로 점화·소화를 반복한다. 기본값은 켜짐 2초·꺼짐 2초이며 Player 접촉 피해는 1이다. 소화 중에는 불꽃 Collider와 피해 처리를 끄고, 재점화 시 여전히 겹쳐 있는 Player에게 피해를 적용한다. `Base/WestSouth` 바닥의 후보를 확률 배치하며 대표 방에서 고블린·아이템 조합을 확인했다.
- `Saw`는 `SawPatrol`로 시작 위치와 오른쪽 끝 사이를 왕복한다. 기본 이동 거리는 3유닛, 속도는 초당 2유닛이며 Player 접촉 피해는 1이다. 이동 거리와 속도는 프리팹에서 조절한다. 방에는 톱니의 크기와 전체 이동 경로를 포함한 공간을 확보하고 실제 통과를 확인한다. 현재 정적 검사는 후보 기준점과 지정 공간을 검사하며 Collider가 이동 경로 전체에서 공간 안에 들어가는지는 보장하지 않는다.
- `Assets/Prefabs/Trap/`의 SpikeHead·SpikedBall·FallingPlatform은 외형·Collider 및 일부 애니메이션이 준비된 상태다. 함정별 동작·피해 처리와 설치 조건을 구현하고 검증한 뒤 연결한다. 용암은 에셋과 동작을 정하고 단일 위치 슬롯과 영역 배치 방식을 비교해 결정한다. 함정별 설치 조건, 생성·미생성, seed 재현성과 대표 조합의 실제 Player 통과를 확인한다.

## 난이도별 출현 확률 계획

- 맵 설정에 난이도 ScriptableObject를 직접 지정한다. 일반 몬스터·엘리트 몬스터·아이템·함정의 출현 확률을 각각 설정한다.
- 방 역할과 설치 조건에 맞는 슬롯에서 난이도별 확률로 출현 여부를 먼저 결정하고, 출현할 때 슬롯에 등록된 후보 중 가중치로 종류를 고른다. 빈 상태는 출현하지 않을 때 적용한다. 난이도별 확률과 슬롯 후보 가중치의 역할이 중복되지 않도록 기존 빈 상태 가중치를 전환한다.
- 슬롯 수에 따라 맵의 실제 출현 수가 달라진다. 일반 방과 선택 방의 아이템 확률을 구분할 필요가 있는지는 보상 설계 시 결정한다. 설치 공간·보호 영역·필수 경로 통과 조건은 난이도와 관계없이 적용한다.
- 확률 0%와 100%, 후보별 가중치, 방 역할과 함정 설치 조건을 확인한다. 같은 난이도 설정·카탈로그·코드와 seed에서 같은 결과가 나오는지 검증한다.

## 검증 기준

- 카탈로그의 Variant ID가 고유하고 Base의 출입구·필수 통로·변형 및 슬롯 설정이 의도대로 상속된다. Base 변경 후 Variant와 수동 검증 표시의 동작을 확인한다.
- 닫힌 방과 필수 경로·시작·Goal에 필요한 후보가 있고, 검증된 분기와 왕복이 가능한 조건에서 선택 방이 연결된다. 여러 seed의 계획·생성과 같은 입력의 재현성을 확인한다. 카탈로그 구성이나 ID 변경으로 이전 seed의 결과가 달라질 수 있다.
- 각 방의 고정 지형·패턴·확률 셀 조합에서 출입구와 착지면을 확보하고 방·패턴 경계의 그래픽과 배경·장식의 가독성을 확인한다.
- 일반 경로 방과 선택 방에 역할에 맞는 콘텐츠만 생성되고 같은 seed에서 선택이 재현되는지 확인한다. 지형 변형과 콘텐츠의 설치면·공간 및 실제 Player 이동과 상호작용을 확인한다. 엘리트는 프리팹 연결 후 별도로 확인한다.
- 지형이나 충돌을 변경한 조합은 실제 Player의 이동·점프·대쉬로 해당 진입과 진출을 확인한다. 반복 검증이 많아질 경우 범위를 먼저 확인받는다. Player 조작 후 입력 장치와 콜백을 정리하고 상태와 Console을 확인한다.
- 설정을 참조하는 씬·에디터 도구·테스트가 Nova 카탈로그로 생성할 수 있고, 에셋의 참조가 유지되어야 한다. 사용하지 않는 Base 전용 설정·카탈로그는 참조를 확인하고 정리한다.

각 단계가 끝나면 결과를 보고하고 다음 단계 진행을 기다린다.
