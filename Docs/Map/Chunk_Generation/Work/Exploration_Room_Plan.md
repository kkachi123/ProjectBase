# 탐사형 방 구조와 콘텐츠 배치 계획

## 목표

출입 구조별로 다층 탐색이 필요한 방을 구분하고, 경로 선택이 아이템과 전투 배치로 이어지게 한다.

## 현재 조건

- 방은 20×20 셀이다. 좌우 출입구는 y `4~7`에 있으며 `Horizontal` Base는 양방향 통과와 상단 지형 변형을 제공한다. `NorthWest_Tiered`는 북쪽에서 서쪽으로 내려가는 다층 방이다.
- Player 이동 설정은 지상 속도 5, 공중 속도 4, 점프 힘 8, 대시 거리 5, 공중 대시 1회다. 점프·착지 가능 여부는 실제 충돌과 조작으로 확인한다.
- 주 경로는 좌우 이동과 하강으로 계획하며, 방은 출입구와 검증된 진입→진출 방향에 맞춰 선택한다. 새 Base 그룹과 Variant를 카탈로그에 추가하면 같은 seed의 방 선택이 달라질 수 있다.
- Goblin 설정의 `MaxTargetHeightDifference`는 1이다. 층이 나뉜 상황에서 인식·추적과 목표 처치 가능 여부를 확인해야 한다.

## 대표 방: 상층 우회 회랑

- **역할과 출입구:** 일반 주 경로 방. 서·동 출입구를 사용하고 서→동, 동→서 통과를 각각 확인한다.
- **이동 구조:** 아래층은 양쪽 출입구를 잇는 기본 통로다. 양쪽에서 올라갈 수 있는 짧은 단차를 거쳐 상층 발판과 보상 공간에 접근하고, 아래층으로 돌아올 수 있게 한다. 상층 접근에 벽 점프나 대시를 필수로 요구하지 않는다.
- **구분:** 기존 `Horizontal`의 상단 변형은 선택된 패턴에 따라 달라진다. 이 방의 상층 접근로는 보상 접근을 위한 고정 지형이므로 별도 Base로 제작한다.
- **컨셉:** 숲에 묻힌 폐허 회랑. Nova 에셋의 지형과 배경으로 상층 발판의 존재와 보상 위치를 알아볼 수 있게 한다. 장식은 출입구·발판·몬스터를 가리지 않도록 한다.
- **콘텐츠 구상:** Variant에 아래층의 일반 몬스터 후보 슬롯과 상층의 아이템 후보 슬롯을 각각 둔다. 몬스터는 진입 직후 피할 수 없게 배치하지 않고 대응 공간을 확보한다. 아이템은 현재 확률 선택을 사용하므로 나오지 않는 경우에도 지형만으로 상층 탐색이 가능하다. 함정은 동선·가시성·회피 공간을 확인한 뒤 적합할 때만 배치한다.

```text
       상층 발판 ── 아이템 후보 ── 상층 발판
          ↗                         ↘
서쪽 입구 ───── 아래층 기본 통로 ───── 동쪽 출구
                  몬스터 후보
```

그림은 동선 개념도다. 발판 좌표·높이·배경과 콘텐츠의 최종 위치는 제작 및 Player 검증 후 결정한다.

## 제작 범위와 순서

1. 대표 Base 1개와 이를 상속한 Nova Variant 1개를 제작한다. Base에는 고정 지형·출입구·통로와 설정 컴포넌트, Variant에는 배경과 콘텐츠 후보를 둔다.
2. 우선 고정 지형과 기본 통로를 검증하고 `Passages`에 실제 통과한 방향만 기록한다. 상층 이동의 성공과 복귀를 확인한 뒤 검증 표시를 설정한다.
3. Variant에 몬스터·아이템 후보를 설정하고 설치 조건, 등장 유무와 각 방향에서의 접근·전투를 확인한다. 함정을 추가한다면 함정의 유무와 콘텐츠 조합도 확인한다.
4. 검증된 Variant를 카탈로그에 등록하고 여러 seed의 맵 생성·연결과 같은 설정·seed의 재현성을 확인한다. 아래 목록의 출입 구조별로 기존 방과 새 후보를 비교해 제작 대상을 확정한다.
5. 선정한 구조의 Base와 Nova Variant를 순서대로 제작·검증하고, 기존 방의 콘텐츠를 검토해 필요한 설정을 조정한다. 각 단계가 끝나면 결과를 보고하고 다음 지시를 기다린다.

## 확장 범위와 판단 기준

- 일반 주 경로에서 사용하는 출입 구조를 아래 목록으로 구분하고 각 구조에 다층 후보를 하나씩 검토한다. `NorthWest`와 `NorthWest_Tiered`처럼 같은 출입 구조를 가진 기존 Base는 함께 비교한다. 해당 구조의 기존 다층 방이 목적을 충족하면 재사용하고, 새 Base가 필요하면 그 구조에 하나를 제작한다. 각 Base에는 Nova Variant 1개를 연결한다.

| 출입 구조 | 현재 비교할 Base | 검토할 이동 경험 |
| --- | --- | --- |
| 서·동 | `Horizontal` | 좌우 통과와 상층 보상 우회 |
| 북·서 | `NorthWest`, `NorthWest_Tiered` | 기존 다층 하강과 상층 탐색의 적합성 |
| 북·동 | `NorthEast` | 하강 후 출구와 상층 공간 접근 |
| 서·남 | `WestSouth` | 진입 후 하강과 상층 우회 |
| 동·남 | `EastSouth` | 진입 후 하강과 상층 우회 |
| 북·남 | `NorthSouth` | 연속 하강 중 발판과 탐색 |
| 북·동·서 | `Arrival` | 하강 후 양쪽 출구와 상층 탐색 |
| 서·동·남 | `Down` | 좌우 통과와 하강 갈림길 |
| 북·동·남·서 | `DownThrough` | 하강·좌우 통과와 분기 동선 |

- 위 표는 검토 목록이며 새 방 제작 확정 목록이 아니다. 시작·Goal·막다른 선택 방과 닫힌 방은 역할·왕복 조건을 따로 비교해 다층 구조가 필요한 경우만 제안한다.
- 각 출입 구조는 **기존 다층 방 재사용 / 새 Base 제작 / 추가하지 않음** 중 하나로 결정하고, 기존 방과의 차이, 이유, 컨셉, 출입 방향, 콘텐츠와 검증 범위를 기록한다. 미결정 항목을 완료 처리하지 않는다.
- 새 Base 후보는 다음 조건을 **모두** 만족해야 한다.
  1. 기존 Base와 대표 방의 이동 경로를 비교해, 다른 플레이 선택이나 접근 방식이 필요한 지점을 구체적으로 설명할 수 있다. 예: 같은 보상을 얻는 길이 아니라 서로 다른 높이의 통로 중 하나를 선택해 출구로 가는 구조.
  2. 기존 Base의 콘텐츠 위치, 지형 패턴 또는 Variant 설정만으로 같은 경험을 만들기 어렵고 고정 지형의 변경이 필요하다. 배경 차이, 출입 방향 확보나 후보 수 증가만으로는 새 Base를 추가하지 않는다.
  3. 현재 Player의 이동 능력과 20×20 방·출입구 규격으로 구성할 수 있으며, 필요한 출입 방향과 콘텐츠·함정의 검증 범위를 정할 수 있다.
- 판단에는 기존 일반 주 경로 Base와 대표 방을 비교하고, 서로 다른 seed의 맵 미리보기 3개 이상에서 구조와 반복을 살펴본다. 미리보기만으로 조작·재미를 확정하지 않으며, 실제 Player 검증 결과와 함께 근거를 기록한다. 3개 표본은 전체 출현 빈도를 보장하지 않는다.
- 기존 출입 구조별 검토와 선정된 후보의 제작·검증을 마치면 확장을 종료한다. 목록 밖의 새 출입 구조나 추가 후보가 필요하면 이유와 작업 범위를 보고해 방향을 결정한다.
- 기존 일반 경로 Variant 11개는 전투 대응 공간·아이템 접근·함정과의 관계를 검토한다. 문제가 확인된 방만 콘텐츠 설정을 조정하며, 위치 변경은 설치 조건과 실제 접근성을 확인한다. 모든 방을 동일한 구성으로 바꾸지 않는다.
- 추가 Base 제작 전 컨셉, 기존 방과의 차이, 필요한 출입 방향·콘텐츠와 검증 범위를 정리한다. 새 구조가 기존 카탈로그 선택 빈도와 seed 결과에 영향을 줄 수 있음을 확인한다.

## 완료 기준

- 대표 Base 1개와 Nova Variant 1개가 카탈로그에 연결되고, 서→동과 동→서로 실제 Player가 통과한다.
- 양쪽 접근 방향에서 상층 보상 공간에 도달하고 아래층으로 복귀할 수 있다. 아이템이 생성된 경우 실제 획득을 확인한다.
- 몬스터 생성·미생성 시 동선과 대응 공간을 확인한다. 함정을 배치한 경우 생성·미생성의 통과와 가시성·회피 공간도 확인한다.
- 방 경계·RuleTile 표시, 설치 조건과 맵 연결을 확인하고 같은 설정·seed의 결과가 재현된다. 미확인 조합은 진행 현황에 기록한다.
- 표의 모든 출입 구조와 별도 역할 방의 검토 결과·이유를 기록하고, 선정된 Base·Variant와 필요한 기존 방의 콘텐츠 조정을 마친다. 추가 Base의 출입 방향·콘텐츠·카탈로그 연결도 같은 기준으로 확인한다.
- 방 단독 이동은 별도 테스트 씬에서 실제 Player와 가상 입력으로 확인한다. 실제 맵 연결과 Run 흐름은 Title → InGame에서 확인한다. 반복 검증 범위가 커지면 횟수를 안내하고 확인받는다.
