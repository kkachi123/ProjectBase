## 수동 보정이 필요한 이유

자동 변환은 `.`만 `This`로 만들고, `X`는 `DontCare`로 둔다. 즉 `X` 위치에 이웃 타일이 **없어야 한다**는 조건은 설정하지 않는다.

이 방식은 패턴이 겹칠 수 있다. 예를 들어 내부 타일과 경계 타일이 모두 일부 조건을 만족할 때, 우선순위에 따라 의도와 다른 Sprite가 선택될 수 있다. 따라서 실제 `WOODS_Ground`에는 다음 보정을 적용한다.

- 내부·평면 변·외곽 코너를 우선 검증한다.
- 모서리가 비어야 하는 경우에는 해당 위치에 `NotThis` 조건을 명시한다.
- 같은 연결 패턴의 Sprite는 첫 번째만 쓰지 않고, 시각적으로 동등한 변형일 때만 `Random` 출력 후보로 묶는다.
- 모든 패턴을 강제로 채우지 않는다. 확신이 낮은 `WOODS_14`, `15`, `22`, `24`, `27`은 테스트 Tilemap에서 확인한 뒤 포함한다.

## 제외 및 분리

| 범위 | 처리 |
| --- | --- |
| `WOODS_29–44` | 경사 지형. `WOODS_Ground`에 넣지 않고 별도 경사 그룹으로 유지한다. |
| `WOODS_0–10, 45–60, 65–69, 71–72, 75–76, 78, 80` | 특수·장식·플랫폼 후보. 이번 RuleTile에서 제외한다. |

## 3단계 생성 범위 제안

1. `WOODS_Ground` RuleTile 하나만 생성한다.
2. 우선 포함할 대표 규칙은 `1, 19, 20, 23, 25, 70, 73, 81, 82`로 제한한다.
3. 불확실한 전이·짧은 모서리 규칙(`11, 13–15, 22, 24, 27`)은 테스트 Tilemap 결과를 보고 추가한다.
4. 원본 Tile 에셋과 `WOODS_Ground_Slope` 후보는 수정하지 않는다.

## 생성 결과

- 생성 에셋: `Assets/Prefabs/BackGround/Floor/RuleTiles/WOODS_Ground.asset`
- 규칙 수: 9개 (`WOODS_1, 19, 20, 23, 25, 70, 73, 81, 82`)
- 기본 Sprite: `WOODS_1`
- Collider Type: `Sprite` (원본 Tile 설정 보존)
- 각 규칙은 여덟 이웃 위치 모두에 `This` 또는 `NotThis`를 명시해, 자동 분석의 `DontCare` 중첩 문제를 방지했다.
- 에셋 YAML 직렬화에서 9개 규칙, 8개 이웃 위치, Sprite 참조 및 Collider 설정을 확인했다.
- `Rectangular Palette.prefab`의 `Layer1` 빈 셀 `(-3, -8, 0)`에 `WOODS_Ground`를 추가했다. 기존 팔레트 Tile은 덮어쓰지 않았다.
- 저장하지 않는 임시 Tilemap에서 8방향이 모두 연결된 내부 구성은 `WOODS_1` Sprite를 반환하는 것을 확인했다.

## 남은 검증

Pipeline의 연속 `eval` 요청이 간헐적으로 연결을 잃어 경계·코너 규칙의 임시 Tilemap 렌더 검증은 아직 실행하지 못했다. 연결이 안정화되면 직선·사각형·오목/볼록 코너·통로 테스트를 수행한다.
