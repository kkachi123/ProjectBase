# Plan_Guide

AI가 질문·제작 지시를 검토하고 Plan 문서를 작성하거나 정리할 때 적용한다. **판단과 근거를 제시하고, 목표·변경 범위·핵심 작업 단계·검증 기준을 요약한다. 구현 결과를 바꾸는 제약과 결정 사항은 유지한다.** 사용자가 지정한 양식·필수 항목이 있으면 우선한다.

## 1. 검토와 의견 제시

- 질문과 제작 지시에 답할 때 사용자의 의견을 검토하고 자신의 판단과 근거를 함께 제시한다. 단순히 동의하거나 요청을 되풀이하지 않는다.
- 다른 의견, 잘못된 전제, 선택에 따른 장단점은 분명히 설명한다. 확인된 사실과 제안·추정을 구분한다.

## 2. 작성 원칙

- 목표는 해결할 문제와 완료 후 동작을 1~2문장으로 쓴다.
- 변경 범위는 관련 파일·기능과 변경 이유만 적는다. 재사용 대상이나 제외 범위는 실제 구현 범위를 구분하는 데 필요한 경우에만 명시한다.
- 대화 중 나온 다른 게임·방식, 채택하지 않은 제안, 선택·합의 과정, 이번 대화의 작업 상태를 계획서 본문에 옮기지 않는다. 최종 제작에 필요한 동작·결정·제약을 직접 적는다.
- 대화에서 언급됐다는 이유로 제외 사항이나 부정형 설명을 추가하지 않는다. 해당 문장을 지워도 구현 대상·동작·의존성·검증 기준이 달라지지 않으면 삭제한다. 책임 경계나 호환 조건처럼 구현에 영향을 주는 제약은 유지한다.
- 작업 단계는 실행 순서대로 적고, 각 단계의 작업과 결과가 드러나게 쓴다. 단계 수는 작업 규모에 맞춘다.
- 검증 기준은 관찰 가능한 결과로 쓴다. 컴파일·연결 확인·실제 동작 확인을 필요한 만큼 구분한다.
- 구현에 필요한 책임 경계·API 계약·의존성·전이 우선순위·중단 정책은 짧게 남긴다. 간결함을 위해 필수 조건을 생략하지 않는다.
- 현재 구현은 소스를 확인하고 적는다. 예정된 변경·가정·미확정 사항을 현재 동작처럼 표현하지 않는다. 결과를 바꾸는 미확정 사항만 확인 대상으로 남긴다.
- 배경 설명·전체 코드·긴 의사 코드·반복 체크리스트·과거 작업 이력은 줄인다. 상세 명세가 필요하면 별도 문서를 연결한다.
- 계획서를 수정할 때 '이전 계획을 유지하며~' 같은 메타 설명이나 변경 이유를 본문에 넣지 말고, 최종 완성된 계획서 본문 내용만 깔끔하게 출력한다. 유지되는 항목과 변경되는 항목은 별도의 서두나 설명 없이 내용 자체에 반영한다.
- 숙련된 게임 기획/프로그래밍 문서 작성자로서, 수정된 최종 기획서안만 군더더기 없이 간결하게 작성한다. AI가 작성한 초안은 검토 후 불필요한 항목을 제거하고, 핵심 내용만 남긴다.

## 3. 기본 구조

| 항목 | 남길 내용 |
| --- | --- |
| 목표 | 해결할 문제와 최종 동작 |
| 변경 범위 | 수정·추가할 파일/기능과 핵심 변경 |
| 핵심 단계 | 실행 순서와 단계별 결과 |
| 검증 기준 | 성공을 판단할 확인 항목 |

설계 결정·제약·확인할 사항은 필요한 항목 아래에 짧게 붙인다. 복잡한 작업은 의존성이나 위험을 이해할 만큼 설명하되, 같은 내용을 여러 섹션에 반복하지 않는다. 단순한 작업은 항목을 합쳐도 된다.

## 4. 작성 틀

아래 틀을 작업에 맞게 채우고, 불필요한 항목과 안내 문구는 제거한다.

```markdown
# {작업명} 계획

## 목표

{해결할 문제와 완료 후 동작}

## 변경 범위

- `{파일 또는 기능}`: {핵심 변경과 이유}
- 필요한 제약·결정: {구현에 영향을 주는 조건이 있을 때만 작성}

## 핵심 단계

- [ ] {먼저 수행할 작업과 결과}
- [ ] {다음 작업과 결과}

## 검증 기준

- {정상 흐름에서 확인할 결과}
- {관련 경계·중단 조건 또는 기존 기능 영향 확인}
```

## 5. 갱신과 마무리

- 구현 중 계획 갱신이 요청되면 실제 완료한 작업만 체크하고, 미검증·수동 확인 대기는 짧게 표시한다.
- 범위나 구현 방향이 바뀌면 목표·변경 범위·단계를 최종 방향에 맞춘다. 설계 근거는 최종 구현을 이해하는 데 필요한 내용만 남긴다.
- 저장 전 중복 설명과 불필요한 항목을 제거하고, 다른 AI가 문서와 연결된 소스만으로 작업·검증 범위를 파악할 수 있는지 확인한다.
